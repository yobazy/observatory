# Review of what merged since 2026-10-30 (2026-11-11)

Review of the changes merged after `555c1d1` (#127, 2026-10-30) through `origin/main` at `9e8f30d` (v0.16.0): 76 commits, 233 files. Two reviewers read the frontend (lead, triage, park, budget code; review, push, PR, Settings and component code) and one read the Rust side. Each candidate was checked against the code before it was counted. Fixes were made only where a test reproduced the defect first.

## Fixed

1. **Preview paths could climb out of an opened folder.** `PreviewScope::allows` compared path components, so `root/../secret` counted as inside `root` while the read followed the `..`. `read_preview_text` and the new `read_preview_bytes` read through it. Now any path with a parent component is refused. Test: `the_scope_does_not_walk_out_through_dot_dot` (`src-tauri/src/preview.rs`). Commit e2a0ff6.
2. **Two tasks queued in one millisecond shared an id.** `newTaskBatch` used the clock in milliseconds as its batch id. A lead's reply can start several tasks in a row, so they got the same batch and task ids, and the lead's follow-up tracked the wrong task. A counter now makes each id unique. Test: `two tasks queued in the same millisecond get their own batch and task ids` (`tests/cap.test.mjs`). Commit c253ecd.
3. **A thread's stuck flag was dropped when its turn couldn't be read.** A failed `thread_turn` was treated as a turn with no errors, which cleared the flag and marked the turn as read, so it wasn't retried until the status moved again. A failed read now leaves the session's flags alone and is retried on the next pass. Test: `a turn that cannot be read keeps the flag it had, and is read again` (`tests/stuck.test.mjs`). Commit 09a3a4c.

## Found, not fixed

Each of these is reported with its evidence. Those marked "no test" could not be reproduced under `node --test`, because the module imports React or Tauri.

- **Checks come from the thread's own checkout and run after every turn** (`src/nebula/reviewRunner.ts`, `checksFor`). When a card has no saved checks, the checks are drafted from the thread's worktree (CLAUDE.md `## Checks`, or `package.json` scripts), and `review.rs` runs them with `sh -c`. An agent that edits its own worktree's test script gets that script run without anyone reading the diff. The agent already has shell access in its own turn, so this adds little, but the policy deserves a decision. Needs Bazil.
- **Saving prefs can drop keys** (`src/nebula/theme.ts`, `savePrefs`). A key absent from the saved object counts as removed, not only one set to `undefined`. A save from a stale render closure can therefore delete keys written in the background (for example `ideas`, `parkKeep`). Likely fix: count only keys present with value `undefined` as removed. Not fixed: `theme.ts` imports React and Tauri, so it has no node test yet.
- **Clean-up can force-delete a branch that gained commits** (`src/nebula/prs.ts`, `cleanUp`). `landed` is decided before the `DeleteWorktree` await, and the branch is then deleted with `-D` without a re-check. A commit made in that window would be lost if unpushed. No node test (Tauri imports).
- **"Closed" and "archived" can be reported after a failed archive** (`src/nebula/verdicts.ts`, `closeThread`; `src/nebula/leadRunner.ts`, `answerLeadAsk`). `closeThread` calls `void request("ArchiveAgent")`, and the lead is told "the user archived X" even when the request fails. Likely fix: return the promise and have the lead's archive await it. No node test (Tauri imports).
- **Two STARTs racing with transcript-fed actions.** A project lead with actions on can launch tasks from text that came from a transcript (turn summaries, triage). Whether that is acceptable is a design question: START lines need a user answer, or transcript text should stay out of acts-enabled leads. Needs Bazil.
- **Top lead can be nudged or asked by project leads** (`src/nebula/leadActions.ts`, `decide`). Lead threads are not excluded from NUDGE/ASK targets. Rate-capped at 3 nudges an hour per thread. Not fixed.
- **A failed reply read can overwrite a newer one** (`src/nebula/leadCalls.ts`, `noteReply`). Reads have no sequence number, so a slow earlier read can land after a newer one. Not fixed, no node test (React import).
- **`replyToAct` compares entry numbers only** (`src/nebula/leadActions.ts`). The S29 notes say a restarted session renumbers entries from 0, while `askKey` and outcomes use the reply time. A renumbered reply can be skipped until its number passes the old one. Not fixed; a test would show it under `tests/leadActions.test.mjs`.
- **Budget holds are off until the first usage scan** (`src/nebula/budgetHold.ts`). `s.usage` is null until the scan lands, so tasks can launch past the cap at relaunch. Not fixed.
- **"Failed twice" label survives a fresh prompt** (`src/nebula/review.ts`, `reviewedLabel`). The `stuck` label ignores the key and the fresh round. Not fixed.
- **Failed verdict read is cached** (`src/nebula/verdicts.ts`). A failed `thread_turn` is stored as "no verdict" under the current status stamp. Low impact.
- **Decisions read failure cached as "nothing waiting"** (`src/nebula/decisions.ts`). Same pattern. No node test.
- **Parking can archive a thread resumed in the meantime** (`src/nebula/park.ts`, `parkThreads`). The due-check is not repeated after `addIdeas` awaits. Not fixed.
- **Card dialog reverts fields changed while it was open** (`src/components/CardDialog.tsx`). Only `lead` is refreshed. Low impact.
- **Follow-up send failure keeps the failed label** (`src/nebula/review.ts`, `reviewPass`). A rejected `send` saves the record with its error, but the queue label still reads "Fixing" until the next review. The next status change re-runs the review, so it is not stuck forever. Low.

## Ruled out

- Every `invoke` name in `src/` is registered in `lib.rs`, and the argument names match their Rust parameters.
- PR state words: gh's upper-case `MERGED`/`CLOSED` are mapped correctly in `prs.ts` and `prwatch.ts`. `gh_pr_merge` pins the head commit.
- Push path: `git_push_ff` never forces, refuses the main branch, and ignores `branch.<b>.merge` as a destination. The frontend's `ownUpstream` agrees with the Rust side.
- Review: the review pass is serialized, and a restarted thread's result is discarded.
- Transcript reads: the session id is validated (`plain_id`) before it becomes a path.
- `save_note` strips path separators and uses `create_new`.
- `write_desktop_prefs` keeps keys it isn't sent and refuses a corrupt file rather than overwriting it.
- `write_atomic` creates parent directories, so a debug build's `dev` folder is created on first save.
- `kill_group` uses `-s KILL -- -pgid`, which is the procps-safe form.
- Lead action caps and `nextLaunchable` lanes hold.
